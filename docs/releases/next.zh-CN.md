## 新增

- 面向 agent 的 MCP 服务器（`nsh-notify-mcp`）：列出未读通知、在所有来源里搜索、读取一条通知的完整内容、标记已读和列出通知来源，支持 stdio 和 HTTP，用 API key 认证。Claude Code、Codex 和 Cursor 的配置见 `crates/mcp/README.md`。
- 通知收件箱的地基：邮件开始出现在与其他来源统一的 feed 里，服务端新增 source 管理接口（新建、改名、暂停、删除），每个来源带一个只在创建时显示一次、可轮换的接收地址 token。Webhook、Gotify 和 ntfy 的实际接收在下一个改动里，App 里的 feed 在其后。
- 签名：每个账号一个（设置 → 账号的菜单 → 签名），支持**粗体**、*斜体*和链接。会添加到新邮件以及回复和转发中（可分别关闭），像 Gmail 一样放在引用的原邮件上方，并同时以纯文本和 HTML 发出。在写信时切换发件账号会换成对应的签名，除非你改过它。本地模式保存在本机，云端模式保存在服务器上。

## 改进

- 键盘与读屏支持。所有控件都可以用 Tab 聚焦（带 Material 焦点框），用回车或空格触发；按 `?`（或设置 → 帮助）可以查看快捷键列表，按键名称随平台显示。读屏会把提示条读成错误提醒或状态播报，也会读出邮箱、搜索、侧栏和工具栏的名称，列表行按未读、发件人、封数、主题、日期朗读。
- 大邮箱：首次同步改为分页进行，列表先显示最新一页，其余邮件继续到达，进度显示在邮箱栏。中途停止后，下次同步从停下的地方继续，而不是从头再来。新增“加载更早邮件”：滚动到文件夹末尾时按页往回取，加载后的旧邮件也能被搜索到。
- 大邮箱下列表依旧流畅。滚动和加载更早的邮件只复用少量行，不再渲染整个邮箱；同步的开销也不再随已加载的行数增长：新邮件出现在第一页，下面的行保持原位置（此前，滚动较深时一次同步会重新加载并重绘全部内容，加载 1 万封邮件时在 Web 上卡顿 350 ms，现在为 50 ms）。翻页超过 500 个会话后不会再被截断回第一页。200 封邮件的会话打开时只列出首尾几封，**更多**每次展开 25 封，**收起**可以再折回。
- 全面改进空状态、加载与失败状态。空文件夹会说明是哪个文件夹，并在合适的地方提供“写邮件”；搜索在输入前给出提示，进行中显示加载指示，失败时说明原因并提供“重试”。邮箱加载失败、邮件打不开、同步失败都会告诉你下一步怎么做：列表内、阅读窗格内以及带重试按钮的横幅。服务器拒绝 IMAP 登录时会解释应用专用密码，并提供该邮箱的帮助链接。
